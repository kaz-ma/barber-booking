## 2. 詳細（Vercel）

### 2.1 Hobby の商用利用不可（Fair Use）
- 「As stated in the fair use guidelines, the Hobby plan restricts users to non-commercial, personal use only.」— [Hobby Plan](https://vercel.com/docs/plans/hobby)（Last updated September 14, 2026）
- 「Commercial usage is defined as any Deployment that is used for the purpose of financial gain of anyone involved in any part of the production of the project, including a paid employee or consultant writing the code. Examples … Any method of requesting or processing payment from visitors of the site / Advertising the sale of a product or service / Receiving payment to create, update, or host the site / Affiliate linking … / The inclusion of advertisements」「Asking for Donations does not fall under commercial usage.」— [Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)（Last updated September 14, 2026）
- 本案件は「美容室（営業中の事業者）のサービス予約サイト」で、制作を受託すれば「Receiving payment to create … the site」にも該当する。**Hobby で本番運用する前提は成立しない。**

### 2.2 Pro の価格と同梱量
- pricing: 「Pro $20/mo.」「$20 of included usage credit」「Flat Rate CDN with traffic spike protection」「Team collaboration & free viewer seats」「Cold start prevention」「Free custom domain」。Hobby 欄は「$0/mo. The perfect starting place for your web app or personal project.」— [vercel.com/pricing](https://vercel.com/pricing)
- 「Developer seats cost $20 per user / month, while Viewer seats are free」「Unlock the full potential of Vercel Pro during your 14-day trial with $20 in credits」— [Hobby Plan](https://vercel.com/docs/plans/hobby)
- Hobby 同梱（月）: Fast Data Transfer 100 GB、Fast Origin Transfer 10 GB、CDN Requests 1,000,000、Active CPU 4 CPU-hrs、Provisioned Memory 360 GB-hrs、Function Invocations 1,000,000、Image Transformations 5,000、Web Analytics 50,000 events。超過時「you will have to wait until 30 days have passed before you can use the feature again」— 同上
- Pro の従量単価: Function Invocations $0.60/1M、Active CPU「Starting at $0.128 per hour」、Provisioned Memory「Starting at $0.0106 per GB-hr」— [Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)

### 2.3 関数の上限

### 3.6 web-push と Declarative Web Push
- npm: `web-push@3.6.7`（2024-01-16 公開。以後リリースなし）、`engines.node >= 16`、`license MPL-2.0`、`main: src/index.js`、**`"type"` フィールドなし（CommonJS）**。05 の「ESM（"type": "module"）」は誤り。Node 22 / Vercel の ESM プロジェクトからは `import webpush from 'web-push'` で読み込める（CJS の default import）。
- README: 「headers is an object with all the extra headers you want to add to the request.」「contentEncoding is the type of push encoding to use (e.g. 'aes128gcm', by default, or 'aesgcm').」— [README](https://github.com/web-push-libs/web-push/blob/master/README.md)
- ソース（[src/web-push-lib.js](https://github.com/web-push-libs/web-push/blob/master/src/web-push-lib.js) `generateRequestDetails`）: `Object.keys(extraHeaders).forEach(header => requestDetails.headers[header] = extraHeaders[header])` の**後**に `requestDetails.headers['Content-Type'] = 'application/octet-stream'` と `Content-Encoding` を設定。→ `headers` オプションで `Content-Type` を差し替えることはできない。
- WebKit 出荷版の宣言的フォーマット（[Meet Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/)）:
  ```json
  { "web_push": 8030,
    "notification": { "title": "…", "lang": "en-US", "dir": "ltr", "body": "…",
                      "navigate": "https://…", "silent": false, "app_badge": "1" } }
  ```
  「The top level "web_push" value is an homage to RFC 8030 … This is the magic value that opts the rest of your push message into declarative parsing.」「a non-empty "title" value is required」「That's where the required "navigate" value comes in.」「You can test it out on iOS 18.4, iPadOS 18.4, and on the macOS 15.5 beta.」「If your push message arrives to a newer browser, it's handled declaratively by the browser. If it arrives to an older browser, it's handled imperatively by JavaScript」。ブログに Content-Type の要件は書かれていない。
  → 05 の「`Content-Type: application/notification+json`」「`default_action_url`」「`options`」は explainer 段階の案で、出荷版は **JSON 本体の `web_push: 8030` と `notification.navigate`** で判別する。web-push の通常の暗号化送信（`application/octet-stream` + `aes128gcm`）のままこの JSON を payload にすれば、iOS 18.4+ では宣言的に、それ以外では SW の `push` ハンドラで表示できる。Content-Type の上書きは不要（かつ不可）。

## 4. 設計判断への影響

1. **Vercel Hobby は使えない（最重要）。** Fair Use の商用定義（商品・サービスの販売の宣伝、制作・ホスティングの対価受領）に美容室の予約サイトは該当する。04 Q10 の「Vercel Hobby $0」前提は崩れ、**月額の最初の段差は Vercel Pro $20/月（開発者 1 席）**になる。DB が Neon Free のままなら合計は約 $20/月。見積・提案書・運用費の表（07/08）に反映すること。Pro にすると同時に得られるもの: 関数 800s、ランタイムログ 1 日、Cron 毎分（「予約 1 時間前リマインド」が Vercel Cron で実現可能になり、05 の代替案は不要）、WAF ルール 40、Password Protection（$20/プロジェクト追加）、Instant Rollback の任意デプロイ選択、Spend Management。
2. **Neon vs Supabase の推奨は変わらない（Phase 1 は Neon）。** Neon Free の値は公式で確認でき、第三者の 0.5 GB は旧情報。Supabase の pause 判定は「DB への user query が週に数件/日程度あれば回避」で、警告メールが 1 週間前に届き、復旧は Dashboard の Resume project（1 年以内）と判明。年末年始の休業程度で止まる可能性は低いが、運用者が警告メールを見逃すリスクは残る。Supabase を選ぶ場合は Pro $25/月で pause を消すのが確実。`btree_gist` はどちらでも使えるので EXCLUDE 制約の方針は両方で成立。
3. **レート制限は Vercel WAF（Hobby/Pro とも可）＋アプリ側の二段構え。** WAF Rate Limiting は全プランで使え、1M allowed requests/月が同梱。ただし Hobby はルール 1 本（Pro 40 本）。`/cancel/[token]` と予約作成 Server Action の IP 制限は WAF ルール（固定窓 10 秒〜10 分）で粗く、同一連絡先の回数制限などキー付き制御は Upstash Ratelimit（Free 500K コマンド/月、250 MB）か Postgres で行う。Turnstile は 20 ウィジェット・無制限チャレンジで無料。
4. **Server Actions の 1 MB 上限**は予約フォームには十分だが、Phase 2 のカルテ写真アップロードは Server Action 経由にせず、ストレージへの直接アップロード（署名 URL）にする。Vercel 関数本文 4.5 MB 上限も同じ理由。
5. **Drizzle / Prisma とも EXCLUDE は DSL 非対応で確定。** 04 Q3 の「生 SQL マイグレーション」方針を正式採用。Drizzle なら `customType` で `tstzrange` を宣言し `drizzle-kit generate --custom` で制約を手書き。Prisma は `Unsupported("tstzrange")` + マイグレーション編集（shadow DB のため拡張もマイグレーション内で作成）。
6. **Cache Components を前提に設計する。** 16.4 で公式推奨・create-next-app 既定・17 で既定化。空き枠ページの `searchParams`（日付）は `<Suspense>` 配下で読み、`<Link prefetch={true}>` を付けた日付リンクだけが per-link prefetch（リンク 1 本につきサーバー呼び出し 1 回）になることを踏まえ、日付ナビは前後数日分のみ `prefetch={true}` にする。`ensureStatic` で管理画面以外のシェルが静的に保たれていることを CI で担保できる。
7. **Push 実装の修正点。** (a) `web-push` は CommonJS だが ESM から default import で問題なし。(b) Declarative Web Push は Content-Type ではなく **JSON の `web_push: 8030` + `notification.{title,navigate}`** で判別するため、05 のペイロード設計（`title`/`options`/`default_action_url`）をこの形に差し替える。web-push の `headers` で Content-Type は上書きできないが、そもそも不要。
8. **Serwist** は Next 16 で Turbopack ガイド（`@serwist/turbopack` + `app/serwist/[path]/route.ts`）に従う。peerDeps は `next >=14`。05 の推奨どおり Phase 1 は手書き SW + `useOffline` で足り、Serwist は後付けで可。
9. **ツール系の無料枠は確定**: Clerk Hobby 50,000 MRU（ブランド表示あり、セッション 7 日固定 → 管理者 1 名の本案件では Better Auth の方が制約が少ない）、Upstash Free 500K cmd/月、Umami Hobby 100K events/月・1 サイト・6 か月保持、otpauth 9.5.2 を TOTP に採用可。
10. **残る不明点**: Supabase の Vercel Marketplace 無料プラン作成の正式手順（Supabase docs が未完）、Biome の「Prettier 97% 互換」数値の一次出典、Prisma #17514 の現在のステータス本文（検索要約のみ）。いずれも設計判断を変えるものではない。
