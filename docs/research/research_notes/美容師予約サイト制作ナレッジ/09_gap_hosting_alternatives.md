# 09 ギャップ補完: Vercel Hobby 商用不可を受けたホスティング代替案の一次資料確認

> 調査日（全ページの取得日）: **2026-10-10**。[09_gap_infra_tooling.md](./09_gap_infra_tooling.md) §2.1–2.2 で確定したとおり、Vercel Hobby は「Hobby teams are restricted to non-commercial personal use only. All commercial usage of the platform requires either a Pro or Enterprise plan.」（[Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)）であり、営業中の美容室の予約サイトは商用に該当する。本ノートは、**Next.js 16（App Router / Node ランタイム / Server Actions / cron 数本 / Web Push 送信）** の小規模商用サイト（1 人美容師・数百 PV/日・Neon Postgres・Cloudflare Turnstile）を前提に、各ホスティングの公式ページを `curl`（JS 描画ページは Playwright）で直接取得して比較した。引用は原文のまま短く抜粋し、URL と「Last updated」（ページにある場合）を併記する。
>
> 取得できなかった一次資料: ConoHa VPS 料金ページ（Cloudflare のボット検証で 403。Playwright でも通過不可）、GitHub の Issue/Release ページ（本環境のプロキシで 403。代わりに `raw.githubusercontent.com` の CHANGELOG と npm パッケージ本体を参照）。
>
> 判定の凡例: **可** / **不可** / **条件付き** / **不明**（一次資料で確定できず）。

## 3. 推奨

### 3.1 観点別ランキング

**(1) 月額総コスト（本トラフィック・最小構成）**
1. Cloudflare Workers Free — $0（ただし 10 ms CPU と cron 5 本・サブリクエスト 50 の制約で SSR 本番には不適）
2. Cloud Run（min-instances なし）— ほぼ $0（egress 数十円、コールドスタート数秒を許容）
3. Cloudflare Workers Paid — **$5**（約 750 円）
4. Railway Hobby — $5（日本リージョンなし）
5. さくらのVPS 1 GB — 807 円（年払い換算）/ 2 GB 1,594 円
6. Render Starter + cron — $7 + $1〜（シンガポール）
7. Netlify Personal — $9（米国実行。東京は Pro $20）
8. Cloud Run（min-instances=1）— 約 $10
9. Vercel Pro / Deno Pro / Netlify Pro — **$20**

**(2) Next.js 16 での実装リスク（低い順）**
1. Vercel Pro — 開発元。proxy.ts / Server Actions / Cache Components / cron / Image すべて一次対応
2. Cloud Run・VPS・Render・Railway — アダプタ不要で素の `next start`。互換リスクはほぼゼロ（代わりに運用負荷）
3. Netlify — OpenNext（Netlify 版）で「every Next.js release」を検証。Node Middleware に fs 非対応などの軽微な制約
4. Cloudflare + @opennextjs/cloudflare — Next 16 対応だが `proxy.ts` は **experimental**（1.20.3〜）、128 MB メモリ、Images binding 必須、ISR は R2+DO 構成。さらに **Cloudflare 公式が vinext（beta）を既定推奨に切り替え**、OpenNext を「既存アプリ向け」と位置付けた点は中期的な保守リスク
5. Deno Deploy — Next.js ネイティブ対応だが Next 16 の明示なし・リージョン不明

**(3) 1 人開発者の運用の単純さ（単純な順）**
1. Vercel Pro — Git push のみ。cron・ログ・ドメイン・TLS・プレビューが同一画面
2. Netlify — 同上（関数リージョンは Pro 以上）
3. Cloudflare Workers — wrangler + bindings（Images / R2 / DO / Hyperdrive）の設定が増える。DNS を Cloudflare に移す前提
4. Render / Railway — Dockerfile 不要で簡単だが日本リージョンなし
5. Cloud Run — Dockerfile・IAM・Scheduler・ドメイン（LB or Firebase Hosting）を個別に組む
6. VPS — OS からすべて自前

### 3.2 結論

- **第一候補: Vercel Pro（$20/月、東京 hnd1）**
  - 理由: 本プロジェクトは Next.js 16 の最新機能（`proxy.ts`、Cache Components、Server Actions、`after()`）と毎分級の cron、Web Push 送信（Node `crypto`）を前提にしており、**互換性リスクを事実上ゼロにできるのは Vercel だけ**。日本リージョン、コールドスタート対策（Fluid compute / 「Cold start prevention」）、1 日のログ保持、per-minute cron、独自ドメイン + TLS がすべて同梱。1 人美容室の月額 3,000 円前後は、予約サイトが 1 件の予約取りこぼしを防げば回収できる水準で、**開発・保守工数（＝制作者の時間）を最小化する価値が $15/月の差額を上回る**。
  - 条件: Pro の $20 クレジットは数百 PV/日なら余裕で収まる（Function Invocations $0.60/1M、Active CPU $0.128/時）。Spend Management の上限（既定 $200）を**低めに設定**しておく。
- **フォールバック: Cloudflare Workers Paid（$5/月）+ @opennextjs/cloudflare**
  - 採用条件: 月額を 1,000 円未満に抑える必要がある場合。**Free プランは不採用**（SSR の CPU 10 ms 上限は公式が「SSR … typically use 10-20 ms」と述べる水準で、Error 1102 の常態化リスク。cron 5 本・サブリクエスト 50/回は Push 送信の設計を縛る）。
  - 着手前の検証項目（1 日で判定可能）: ① `proxy.ts` を含む本番ビルドが `opennextjs-cloudflare build` で通り、Turnstile 検証・Server Actions・`after()` が `wrangler dev` で動く、② `web-push` の VAPID 署名 + 暗号化が `nodejs_compat` で動く（CPU 時間を Workers Logs で確認）、③ Images binding で `next/image` が期待どおり（5,000 unique transformations/月の Images Free 枠内か）、④ Neon を Hyperdrive 経由にするか `@neondatabase/serverless`（HTTP）にするか決定、⑤ DNS を Cloudflare に移管可能か（Custom Domains の前提）。
  - 将来の決済追加時は Free Services の「credit card information」禁止条項に注意（Paid なら問題なし）。
- **次点（運用を自分で持てる場合）: Google Cloud Run（東京、min-instances なしで ≒ $0 / あり ≒ $10）**。アダプタ不要で Next.js 16 の互換リスクが最小だが、独自ドメインが「preview・本番非推奨」の domain mapping か、Firebase Hosting（Blaze）/ 外部 LB を要する点と、Dockerfile・IAM・Scheduler の構築が 1 人運用には重い。
- **非推奨**: Netlify Free（300 credits はデプロイ 15 credits/回で枯渇しやすく、枯渇時は全プロジェクト停止。関数は米国実行）、Render Free（公式が本番利用を明示的に否定。日本なし）、Railway（実質無料枠なし・日本なし）、共用レンタルサーバー（Node.js 非対応または起動課金型）。VPS は最安だが TLS・更新・監視を 1 人で担う運用コストが本案件の規模に見合わない。
