# ADR-0010: 予約はトップページ 1 枚で行い、空き状況は月単位の GET で一括取得する

## コンテキスト

- デモで、メニュー → 日時 → お客様情報 → 確認 → 完了 が別ページに分かれており、トップでメニューを見たあと予約ページで同じメニューをもう一度選ぶ二度手間があった。「メニューを選ぶと一覧が閉じて選択中の 1 行になり、その下に次の項目が開く」1 枚の構成（参考サイトと同じ）にしてほしい、ボタンを押すのは最後の「この内容で予約する」と確認ページの「予約を確定する」だけにしたい、という依頼があった。
- 日時ページの表示が 3〜6 秒かかっていた（本番で計測）。原因: 1 回の表示で DB へ約 11 往復（メニュー有効確認・最大日数・月の状態・日の枠、それぞれ BEGIN / SET LOCAL / SELECT / COMMIT）し、日付を変えるたびにサーバーでページ全体を作り直していた。関数（既定 iad1）と DB の距離が往復ごとに効く。
- 動作確認中に「問題が発生しました」画面が出た。再公開の直後に古い画面から Server Action を送ると版がずれて例外になる経路、休止明けの DB への接続失敗の経路がある。

## 決定ドライバー

1. 離脱しにくい最短の導線（選択・入力以外のタップは 2 回）。
2. 日付の切り替えは待ち時間なし。初回の空き状況も 1 往復の HTTP で。
3. 空き状況は決してキャッシュしない（AGENTS.md 規則 3）。予約時の再確認・排他制約はそのまま。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| A. トップに 3 ステップをまとめたクライアントコンポーネント＋ `GET /api/availability?menu=&month=`（月の日別状態と各日の空き開始時刻を 1 クエリで返す） | 日付切替は即時、翌月も先読み、HTTP GET なので版ずれの影響なし | Route Handler が 1 本増える（ADR-0004 の一覧に追加） |
| B. 各ステップを RSC のまま、Server Action で月データを取得 | Route Handler を増やさない | Server Action は POST で直列化され、版ずれで失敗する。読み取り用途に向かない |
| C. 現状のページ分割のまま高速化だけ行う | 変更が小さい | 二度手間と画面遷移が残る（依頼を満たさない） |

## 決定

**A を採用する。**

- トップの予約欄（`app/(public)/_components/booking-section.tsx`）: ① メニュー（1 行の選択リスト）→ ② 日時（月カレンダー＋空き時刻のボタン）→ ③ お客様情報（全項目を最初から表示、備考も入力欄で表示）。選ぶとそのステップは「選択中」の 1 行に畳まれ、次が開く（決定ボタンなし）。各ステップは履歴（`?step=`）に積み、ブラウザの戻るで 1 つ前に戻る。入力は従来どおり sessionStorage の下書きに保存。
- 「この内容で予約する」で確認ページ（`/book/confirm`、従来の S-C-04）へ。確定後は完了ページ。
- 旧 URL（`/book`・`/book/time`・`/book/info`）は proxy で `/{locale}?step=…#book` へ 308。
- `GET /api/availability`: `getMonthSlots()` が `queryMonthWithSlots()`（§6 の CTE を共有、過去日は out_of_range）を 1 文で実行。`Cache-Control: no-store`、公開情報のみ（予約者・件数は返さない）、`Server-Timing: db;dur=`。乱用は Vercel WAF のレート制限（対象パスに追加）で抑える。
- `readAvailability()` は `BEGIN READ ONLY; SET LOCAL jit = off` を 1 メッセージで送り、3 往復で読む。DB の一時的な接続失敗（Neon の休止明けなど）は `withDbRetry()` で 1 回だけ再試行。
- 確認ページは Server Action の例外（通信断・再公開直後の版ずれ）を捕まえ、下書きを保ったまま再読み込みを案内する。エラーページの「もう一度試す」は完全な再読み込み。

## 結果

- 良い点: 画面遷移は確認と完了の 2 回だけ。日付切替は通信なし。空き状況の DB 往復は 11 → 3。
- 悪い点: トップページのクライアント JS が増える。空き状況は表示時点の情報なので、確定時に埋まっていた場合は従来どおり日時ステップに戻して案内する（排他制約と再確認は不変）。
