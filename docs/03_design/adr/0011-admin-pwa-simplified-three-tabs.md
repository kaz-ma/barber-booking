## コンテキスト

- 実機で管理 PWA を使ったところ「情報が多すぎてどこを押してどうすればよいか分からない」「普段使いしにくい」という評価だった。
- 主な原因: 今日／週／受信箱／設定の 4 タブ＋ヘッダーの受信箱ボタンで入口が重複、今日画面のタイムライン（時間軸に予約・休み・空きを敷き詰める）と＋ボタンのクイックシート（4 種）、予約詳細の操作ボタンが常に 6〜8 個並ぶ、手動予約・休みのフォームの項目が多い、設定がセグメントタブで画面ごとに説明カードが多い、通知設定に手順表示・端末一覧・ログイン一覧・お知らせカードが並ぶ。
- 店主 1 人が施術の合間に片手で見る用途で、毎日使うのは「今日と近い日の予約を見る」「来店・終了を記録する」「予約や休みを足す」の 3 つ。

## 決定

1. **タブは 3 つ**: 予約（`/admin`）／お知らせ（`/admin/inbox`）／設定（`/admin/settings`）。ヘッダーの受信箱ボタンは廃止（未確認の件数はタブのバッジ）。
2. **予約画面 = 週ストリップ＋その日の一覧**。週表示（S-A-03）はストリップに統合し `/admin/week` は `/admin?date=` へ転送。タイムラインは時刻・お名前・メニューの一覧に置き換え、30 分以上の空きは「空き 18:00〜」のボタン（押すとその時刻で予約追加）として一覧の下に出す。
3. **＋ボタンは 2 択**（予約を追加／休みを入れる）。
4. **予約詳細は「次にやること」1 ボタン**（来店した → 施術を始める → 施術が終わった）。キャンセル系（店から・無断・遅刻）は 1 つのボタンから開くシートにまとめ、予約コード・作成日時・同意・履歴などは「くわしい情報」に畳む。
5. **フォームは 3 区画**（いつ・メニュー／お客様／受けた方法・メモ）。休みは「終日」スイッチと 30 分刻みの開始・終了だけ。
6. **設定は一覧**（メニュー・料金／営業時間・予約のルール／通知・ログイン／お客様）。各画面から説明カード・並べ替え・臨時営業時間の編集・端末一覧などを外した。通知は「オン／オフの状態＋1 ボタン＋テスト通知」、ログインは「Face ID を登録」「ログアウト」「端末をなくしたとき（ほかをすべてログアウト）」のみ。

## 省いたもの（機能としては残るもの）

- 臨時の営業時間（特定日の時間変更）の編集 UI: 特定日を休みにするのは「休みを入れる」で代替できる。DB・空き計算は従来どおり `business_hour_overrides` を読む。
- メニューの並べ替え・後片付け時間の一覧表示: 編集シートには残す。
- 通知の端末一覧・ログイン中の端末一覧・テスト結果の端末別表示: 紛失時は「ほかの端末をすべてログアウト」1 回で足りる。購読の作り直しはテスト失敗時（または「届かないとき」）にだけ出す。

## 結果

- 良い: 主要操作が 1〜2 タップ、1 画面のボタン数が大幅に減る。サーバー側（Server Action、SQL、排他制約、監査）は変更なし。
- 注意: 臨時営業時間の UI が必要になったら設定の営業時間画面に戻す（データモデルはそのまま）。
