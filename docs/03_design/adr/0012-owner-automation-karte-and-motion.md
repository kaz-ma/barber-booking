# ADR-0012: 施術に集中できる仕組み（予約リンク・自動ステータス・カルテ ほか）と控えめな動き

## 文書情報

| 項目 | 内容 |

| 版 | v0.1 |
| 日付 | 2026-10-18 |
| ステータス | Accepted |

## コンテキスト

- 予約の受付・記録・連絡のために、店主が施術の合間にスマホを操作する回数を減らしたい。
- 制約: Vercel Hobby の定期実行は 1 日 1 回まで。外部の定期実行サービスは使わない（店主判断）。
  写真は追加の保存先を使わず今の DB に保存する（店主判断）。お客様への連絡手段は Instagram の DM だけ（OI-10）。

## 決定

| 機能 | 決定 |
|---|---|
| A2/A4/A5 動き | ステップの開閉（0.3 秒）、押下の縮小、地図の道順の描画、読み込みのバーバーポール。CSS 中心、`prefers-reduced-motion` で停止、JS なしでも完成状態を表示 |
| B1 予約リンク | 空き時刻を `GET /api/availability` から選び `/{locale}?menu=…&start=YYYY-MM-DDTHH:MM#book` を DM で送る。開くとお客様情報が開いた状態。時刻が埋まっていれば日時選択に戻す。書き込みは通常の予約パイプライン（再確認・排他制約・Turnstile）のまま |
| B2 自動ステータス | 開始で施術中、表示上の終了で終了（来店日の更新も同じ）。管理画面で日・予約を開いたときと毎晩 3 時に反映。店主が開始後に戻した予約は以後動かさない。無断は施術中・終了から訂正できる |
| B3 カルテ | `karte_records`（来店ごとのメモ）と `karte_photos`（JPEG を DB に保存、1280px・〜150KB に縮小、1 件 600KB・全体 300MB・1 回 6 枚まで、実寸はサーバーで JPEG ヘッダーから読む）。初回の写真で `consents(photo_karte, owner-recorded-1)` を記録。匿名化で削除、エクスポートに含める。本文は監査・ログに書かない |
| B4 次のお客様 | 外部の定期実行がないため push ではなく、今日の一覧の上のカード（施術中／次の予約＋前回カルテ）。名前を push に載せない規則（AGENTS.md 6）とも整合 |
| B5 ストーリー画像 | `GET /api/admin/story`（next/og、1080×1920、今日から 7 日・1 日 1 行）。共有シートで Instagram へ |
| B6 そろそろ来店 | 最終来店から 4/5/6/8 週・1 年以内・次の予約なし・その来店後に未連絡、を一覧。DM 文面コピー、`ig.me` で DM を開く（`customers.instagram_handle`）、「送った」で `last_reminded_at`。自動送信はしない |
| B7 毎週の休み | `recurring_blocks` を予約可能期間ぶん `time_blocks` に展開（保存時と毎晩）。空き計算と排他モデルは変更なし。消した日は再作成しない、予約・休みのある日と定休日は飛ばす |
| B8 カレンダー連携 | `GET /api/calendar/{token}`（webcal 購読）。トークンは 32 バイト・SHA-256 のみ保存、名前は載せずメニューのみ。IP レート制限 |

## 結果

- 良い: 入力（B1）とタップ（B2）が大きく減り、カルテ・次のお客様で準備が画面 1 つで済む。
- 注意: 写真は DB 容量を使う（上限で拒否）。容量が足りなくなったら R2 等への移行を別 ADR で決める。
- 注意: B4 は通知ではない。外部の定期実行を導入する場合は push 化を再検討する。
- migration 0005〜0008 は本番で `DB setup (production)` の `migrate` を先に実行してからデプロイする。
